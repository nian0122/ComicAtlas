# 管理端存储统计

## 统计口径

此页面展示漫画库容量，不代表磁盘已用空间：HQ/LQ 来自数据库登记的就绪文件大小，缩略图来自 THUMBS 目录最近一次完整扫描。回收站、导出产物、临时文件与数据库外的 HQ/LQ 文件不计入漫画库汇总。

- 漫画排除已删除及回收、恢复、永久清理中的生命周期；无媒体的活动漫画仍计入漫画数。
- 活动章节为 DRAFT/READY；活动媒体为 STAGING/READY 的 IMAGE/VIDEO。
- HQ 仅统计 READY 文件；LQ 仅统计 READY 的 IMAGE，视频不计入图片优化容量。
- 存储列表、章节详情与全库汇总共用 SQL 范围；漫画派生统计也遵循上述章节、媒体与质量规则。
- 全库汇总不随存储列表筛选变化。

## 查询与刷新分离

`GET /api/manage/storage/stats` 只查询数据库，组合实时 HQ/LQ 汇总和缩略图成功快照，不访问文件系统或 Redis。删除旧的同步目录扫描适配器、查询服务统计方法及统计缓存注册；旧 Redis 缓存键不再读取，按原 TTL 自行过期。

`POST /api/manage/storage/stats/refresh` 返回 HTTP 202，只受理后台核对请求。独立执行器使用一个工作线程与一个排队位置，通用调度线程只投递任务。手动重复请求合并；页面在 PENDING/RUNNING 时轮询只读接口，卸载页面后停止轮询。

首次还没有成功快照时，`snapshotAvailable=false`、`totalBytes=null`，页面显示待统计而不是零容量。成功后返回 `thumbBytes`、`thumbFileCount`、`thumbUpdatedAt`；快照时间以 UTC 存储，前端转换为当地时间。失败时 `refreshStatus=FAILED`，保留上次成功容量与时间，明确提示核对失败。

## 持久化与可靠性

V34 迁移新增 `storage_capacity_snapshot`，保存成功结果、刷新状态、请求与完成版本。状态为 PENDING/RUNNING/READY/FAILED。

扫描开始捕获 requestedVersion；完成只确认这个版本。扫描期间收到文件变化时，新版本继续保持待处理，避免变更被吞掉。导入最终化、整本回收/恢复/清理、导出后移除漫画等缩略图变化，在业务事务成功提交后通过独立事务登记刷新；回滚不登记。后台启动恢复上次中断的 RUNNING 状态。

成功快照同时保存配置根路径的规范化 SHA-256 指纹。THUMBS 配置路径变化后，旧根容量不再展示，启动时登记新根扫描。

文件遍历不跟随符号链接，一次读取文件属性；缺失目录、访问错误、中断、超时均使本轮失败，不发布部分结果或假零。扫描预算在目录/文件访问之间检查；操作系统阻塞的单次文件访问不能被此预算立即终止。

当前协调器适用于单个管理服务实例，不提供多实例扫描租约。目录扫描不是文件系统原子快照；业务变化触发下一轮核对，外部文件变化由周期校准补偿。

## 配置与升级

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `storage.statistics.refresh-interval` | `15m` | 无业务变更时周期校准 |
| `storage.statistics.scan-timeout` | `2m` | 扫描时间预算 |
| `storage.statistics.poll-interval-ms` | `5000` | 后台检查间隔 |

文件变化防抖 5 秒，扫描失败自动重试至少间隔 1 分钟。手动刷新可以立即重新登记失败任务。

升级需由管理服务执行 V34 迁移，并同步发布配套前端。源代码修改不会自动替换当前运行的服务；旧服务仍会执行原同步扫描。

## 验证

`StorageStatisticsTest` 与 `StorageStatisticsMySqlTest` 分别在 H2 和独立 MySQL 8 测试库执行真实 Mapper SQL 与快照 DDL，覆盖统计范围、异步受理、请求版本、失败保留、重启恢复、事务提交/回滚、根路径变更和扫描异常。Controller 测试验证 GET 不触发扫描、POST 返回 202。相关浏览器测试覆盖首次等待、自动更新、刷新失败保留与接口错误。
