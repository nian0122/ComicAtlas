# 后端架构审计结论

更新日期：2026-09-16。

## Service 契约

本项目的 Service 均作为 Spring 应用服务使用。Controller、MQ Handler 和其他业务服务通过明确的业务方法调用它们；没有需要被多个独立实现替换的端口，因此不为每个内部 Service 增加只有一个实现的空接口。跨边界职责已通过独立应用服务、规划器和适配器拆分。

## Mapper 条件更新

条件更新保留在事务业务服务中，由业务服务同时维护状态机、事务边界和跨表联动。Mapper 只负责执行传入的持久化操作；把业务条件逐一复制成 Mapper 方法会把状态机规则分散到数据访问层，无法改善边界。涉及并发安全的更新仍使用条件更新并检查受影响行数。

以上是对原审计标记的明确结论，不再作为待办事项跟踪。
