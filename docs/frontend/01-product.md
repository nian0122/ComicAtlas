# 01 — 产品定义

**更新日期：** 2026-08-08
**状态：** 与 v1.0 现状同步
**维护者：** ComicAtlas 产品组

> 回答"ComicAtlas 是什么"。不涉及 UI，不涉及技术实现。

---

## 1. 价值主张

> 把分散在各处的漫画收藏整理成一个可搜索、可阅读、可长期维护的个人媒体库。

---

## 2. 产品定位

- **个人漫画仓库**——不是社区、不是商店、不是聚合器
- **负责导入与下载**——统一接收 ZIP / 本地目录（REGISTER）/ EHENTAI 三种来源，并负责 EHENTAI 的下载
- **本地部署**——Docker Compose，跑在自己的机器上
- **阅读优先**——导入完就能看，Reader 是核心体验
- **媒体库思维**——管理 + 浏览 + 搜索，像 Plex/Komga 而非文件管理器
- **管理后台（v1.0）**——漫画工作区、目录/章节、媒体上传、任务中心、批量操作、存储管理、DLQ；删除进回收站（软删除，7 天保留期）

---

## 3. 产品边界

**ComicAtlas 是**：
- 个人漫画的管理、导入、组织和阅读工具
- 本地部署的 Web 应用
- 长期维护的个人媒体库

**ComicAtlas 不是**：
- 漫画下载器
- 在线漫画网站
- 社区或社交平台
- 多用户系统

**暂不支持**：
- 用户系统、多用户
- 评论、评分、收藏同步
- 第三方插件系统（EHENTAI 下载是内置能力，非插件体系）
- 桌面客户端

---

## 4. 用户画像

一个人管理自己的漫画收藏。主要使用 PC 浏览器访问，漫画文件保存在本地磁盘，偶尔通过手机继续阅读。

典型行为：
- 从 ZIP / 本地目录 / EHENTAI 导入漫画
- 浏览、搜索自己的收藏
- 打开漫画阅读，记录进度
- 生成 LQ 以便移动端阅读，管理 HQ 与存储占用

---

## 5. 核心能力

| 优先级 | 能力 | 说明 |
|--------|------|------|
| 1 | 漫画阅读 | 翻页、进度记录、章节导航、图片/视频混排 |
| 2 | 漫画浏览 | 列表、详情、目录树、标签、分类 |
| 3 | 漫画导入 | ZIP / REGISTER / EHENTAI，统一 MANAGED 存储 |
| 4 | 全文搜索 | 关键词 + 标签/分类/来源类型筛选与排序 |
| 5 | 管理后台 | 目录/章节管理、媒体上传、任务中心、批量操作、存储管理（删除进回收站，7 天保留期） |
| 6 | 任务监控 | 导入/管理/导出/恢复任务进度、失败重试 |

---

## 6. 非核心能力

以下能力不作为重点优化对象：

- Dashboard（统计面板）——阅读端首页提供最近阅读/最近导入聚合视图
- 操作日志——阅读端不提供独立日志页面，运维信息走管理端任务中心与 Outbox/DLQ 监控

---

## 7. 产品调性

- **克制**——不堆砌功能
- **快速**——导入快、搜索快、翻页快
- **安静**——没有推送、没有通知轰炸
- **可靠**——像长期使用的工具（Obsidian / Immich / Komga），而不是一次性的 Demo

---

## 8. 设计原则

1. **阅读优先**——阅读页面优先保证内容展示，尽量减少界面干扰
2. **内容优先**——封面和漫画内容比按钮更重要
3. **响应迅速**——所有常用操作都应尽可能即时反馈
4. **简单一致**——同一种操作在整个系统中保持一致的交互方式
5. **渐进增强**——先实现核心能力，再增加高级功能
