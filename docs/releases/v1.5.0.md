# ComicAtlas v1.5.0 发布说明

**版本**：1.5.0
**发布分支**：`main`
**定位**：面向个人用户的本地漫画仓库稳定版本
**发布日期**：2026-08-12
**基线**：自 v1.1.0 标签后的 324 个开发候选提交（`v1.1.0..develop`），Flyway 迁移终点 V20。

## 用户可见功能

本版本相对 v1.1.0 主要带来以下能力（每项均可在发布基线清单 `.omo/evidence/task-1-release-v1-5.txt` 第五节找到实现与测试证据）：

- **漫画管理后台全功能**：漫画工作区（列表、详情、编辑、乐观锁 `version`）、目录与章节管理、媒体重排/回收、任务中心（逐项进度、取消、重试）、Outbox 积压监控、允许操作查询、危险区；前端布局重构并补齐响应式。
- **存储操作统一端点**：LQ 生成、HQ 删除、视频转码、导出、刷新元数据、存储统计统一收敛到 `/api/storage/*` 形态，旧端点全部移除；导出任务全局列表并入任务中心。
- **回收站 TRASH 清单数据库化（V20）**：删除即回收（软删除），7 天保留期后可恢复或永久清理（二次确认），支持对账修复；`trash_manifest` 清单落库，Worker 只读访问。
- **导入目录规范化**：目录自动规范化为目录树 + 章节，支持根混合、嵌套混合、纯媒体子目录与空目录处理，提供批量目录扫描预览；目录自然排序与安全遍历，支持嵌套子目录。
- **标准分卷 ZIP 支持（导出 + 导入闭环）**：`sourcePath` 指向同 basename 分卷组最后一个 `.zip`，缺任一卷直接失败，`.z01` 永不作为入口；导出产物以标准分卷落在宿主机本地目录（无 HTTP 下载）。
- **元数据刷新**：快照 + 原子合并 + 旧布局自动迁移；数据库有记录但磁盘缺失的媒体标记 `HQ MISSING`，保留 LQ/视频/转码状态。
- **视频转码模块化**：非标准视频不再自动转码，标记 `QUEUED` 供手动转码；抽取 `FfmpegTranscoder` 公共核心，清理 `VideoNormalizer` 死代码。
- **枚举化与兼容**：ComicStatus、ChapterLifecycleStatus、ImportTaskStatus、UploadSessionStatus 等枚举化，DB 以 `VARCHAR` 存储，迁移自动处理存量数据。
- **FRP 远端基础设施连接**：`tools/maintenance/manage-remote-infra-frp.ps1` 支持带 token/STCP secret/TLS 的远端基础设施访问，含心跳超时重连。
- **Docker/网关健康检查**：Actuator 健康端点、Nginx 动态解析、Compose 健康检查。

## 兼容性变化

- **sourceType `REGISTER` → `DIRECTORY`（V17）**：导入来源类型统一为 `DIRECTORY`，存量 `REGISTER` 数据由迁移脚本自动转换，`safeValueOf` 兜底未知值。
- **视频转码状态分类（V18）**：非标准视频标记 `QUEUED`，不再自动转码；`transcode_status` 状态机为 `NOT_NEEDED / QUEUED / TRANSCODING / READY / FAILED`。
- **Outbox/阅读历史完整性（V19）**：`outbox_message` / `inbox_receipt` / 阅读历史增加完整性约束。
- **存储操作接口收敛**：`/comics/{id}/lq`、`/admin/storage/comics/{id}/transcode-videos` 等旧端点移除，统一使用 `/api/storage/*`。
- **删除统一进回收站**：旧完整删除链路（`comic.delete` 事件）已移除；删除 = 回收，永久删除 = `purge`（`TRASHED` + 7 天保留期 + 二次确认）。
- **Worker 只读强制**：Worker 数据库账号仅 `SELECT`，HikariCP `read-only=true`，配置契约测试防止回退；Worker 密码无默认值，未设置启动即失败；日志 URL 脱敏。
- **Broker 遗留实体**：已运行 RabbitMQ 中残留的旧 durable exchange/queue/DLQ 不会被自动删除，需人工清理（见部署运维手册）。
- **生产迁移源唯一 `db/flyway`**：历史迁移归档到 `db/migration-archive/`，仅审计保留，不参与 Flyway 执行。

## V17-V20 迁移

| 迁移 | 内容 |
|------|------|
| `V17__source_type_register_to_directory.sql` | REGISTER → DIRECTORY 语义迁移（枚举 + 存量数据） |
| `V18__classify_video_transcode_status.sql` | 视频转码状态分类（非标准视频 QUEUED） |
| `V19__enforce_outbox_and_history_integrity.sql` | Outbox / 阅读历史完整性约束 |
| `V20__trash_manifest_db.sql` | TRASH 资产清单落数据库 |

V1-V16 为 v1.1.0 已存在迁移，本版本保持不可变。升级时 Flyway 按版本号顺序自动执行 V17-V20；生产迁移源唯一为 `api-service/src/main/resources/db/flyway/`。

## 升级步骤

完整升级、升级前检查与升级后检查清单见[部署运维手册的"五、升级"章节](../operations/management.md)，回滚步骤见同一文档的"六、回滚"章节。要点：

1. 备份数据库与存储卷（升级前必须完成）。
2. 拉取新版本并重启：`git pull origin main`、`docker compose -f docker-compose.yml up -d --build`。
3. 观察 Flyway 迁移日志与健康状态（`docker compose logs -f api-service`）。
4. 升级后核对 Outbox 积压、任务中心、回收站列表与兼容端点（见部署运维手册检查清单）。
5. 如需清理 Broker 残留旧 MQ 实体，按部署运维手册"Broker 遗留 MQ 实体清理"执行。

## 已知限制

依据发布基线清单 `.omo/evidence/task-1-release-v1-5.txt` 第七节声明：

- 媒体上传/替换为预留接口能力（后端分块上传可用、当前无前端页面入口）。
- EHENTAI 定位为 API 能力，前端导入页 UI 仅提供 ZIP / DIRECTORY。
- 视频导入不自动转码，非标准视频标记 `QUEUED` 供手动转码。
- 已运行 Broker 残留旧 durable MQ 实体需人工清理（不自动删除）。
- 媒体恢复依赖 HQ 目录与数据库记录一致（storage-recovery）。
