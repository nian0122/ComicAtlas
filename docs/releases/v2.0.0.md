# ComicAtlas v2.0.0 发布说明

**版本**：2.0.0

**发布分支**：`main`

**定位**：面向个人用户的本地漫画仓库稳定版本

**发布日期**：2026-08-16

**基线**：`v1.5.0..v2.0.0`，Flyway 迁移终点 V23。

## 主要变化

- **读写服务拆分**：新增独立 `reading-service`。`/api/manage/**` 路由到管理服务，`/api/**` 路由到阅读服务；阅读进度仍由阅读服务写入 `reading_history`。
- **共享模块收敛**：跨服务 DTO、异常和枚举归入 `comic-shared` 的 contract 边界，实体、Mapper 与存储解析归入 persistence 边界，减少服务间重复定义。
- **管理控制台重构**：漫画工作区、目录与章节、媒体操作、任务中心、回收站和存储页面统一导航与交互，补齐移动端布局和桌面版切换。
- **管理命令管线统一**：LQ 生成/重建、HQ 删除、视频转码和元数据刷新统一走 `comic.management`，移除旧 LQ/HQ 独立消息链路。
- **元数据同步闭环**：导入最终化及管理命令完成后统一触发 metadata 重导出；支持合并调度、原子写入，并保留 HQ/LQ 与视频事实。
- **存储统计修正**：HQ 与 LQ 大小分离，漫画和章节统计从媒体记录重算；存储页面补齐视频大小、转码状态和媒体文件名展示。
- **视频转码增强**：增加分辨率资格判断、硬件编码探测与 CPU 回退，完成事件回传实际产物路径，避免文件名冲突和僵尸任务状态。
- **Worker 容器化**：项目 Compose 纳入 Worker，支持宿主机路径映射；各服务增加内存限制并优化 Docker 构建。
- **稳定性修复**：覆盖导入重试、最终化、恢复扫描、Outbox、回收站、阅读进度、Nacos IPv4 解析及 Nginx 健康检查等问题。

## 数据库迁移

| 迁移 | 内容 |
|------|------|
| `V21__unify_table_collation.sql` | 统一相关表的字符集与排序规则 |
| `V22__add_scan_task_retry_count.sql` | 为目录扫描任务增加重试计数 |
| `V23__separate_hq_and_lq_sizes.sql` | 分离 HQ/LQ 大小字段并迁移旧统计数据 |

升级时 Flyway 会按顺序自动执行迁移。升级前必须备份数据库和漫画存储目录；完整步骤见[部署运维手册](../operations/management.md)。

## 兼容性说明

- 管理接口统一使用 `/api/manage/**`，阅读查询继续使用 `/api/**`；Gateway 路由顺序必须先匹配管理端。
- Worker 纳入项目 Compose，并继续使用只读 MySQL 账号；管理服务和阅读服务使用具备业务写权限的 API 账号。
- 旧 `comic.image.lq.*`、`comic.image.hq.*` 及完整删除消息实体不再由代码声明。RabbitMQ 中既有 durable 实体不会自动消失，需要确认无消息后人工清理。
- `page.file_size` 迁移为 `page.hq_size`，漫画级重复 `file_size` 字段被移除；应用代码和外部查询应改用 HQ/LQ 独立统计字段。

## 已知限制与后续开发

- 稳定导入主流程为 ZIP 和本地目录；EHENTAI 下载对接尚未完成，不作为 2.0 稳定能力。
- 分类与标签支持手动维护，但导入后的自动分类、自动标签尚未实现。
- 媒体上传/替换后端保留预留能力，当前没有正式前端入口。
- 非标准视频不会在导入阶段自动转码，需要在管理端手动触发。
- 已运行 Broker 中的遗留 durable MQ 实体需要人工清理。

## 升级步骤

1. 备份 MySQL 数据库、`.env` 和 `{MANGA_ROOT}` 存储目录。
2. 检出 `v2.0.0` 或拉取 `main`。
3. 检查新增的阅读服务、Worker 和基础设施环境变量。
4. 执行 `docker compose -f docker-compose.yml up -d --build`。
5. 检查 Gateway、API、Reading、Worker 与 Nginx 健康状态，并确认 Flyway 已迁移至 V23。
6. 验证一条 ZIP/目录导入、漫画阅读、阅读进度保存和管理任务链路。

## 发布树边界

`main` 只保留用户运行、部署、运维和用户文档所需内容。Maven Wrapper、开发启动脚本、QA/E2E、测试夹具和迁移工具保留在 `develop`，不进入正式发布树。
